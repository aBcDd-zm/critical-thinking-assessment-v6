# 思衡 V6 六维证据合同

## 适用边界

V6 的六维是对自然对话的**后台证据整理框架**，不是访谈导航器。`v6.2.1` 从真实具体事件开始并沿同一决策主线柔性深入；访谈官不会读取缺失维度，也不能以自然停顿决定结束。每轮后独立任务先做来源归属和服务端资格判定，再更新当前完整证据快照。只有至少 8 个已保存用户回答且六维全部充分时系统才主动显示完整报告入口。8 是最低保护线而非固定结束点；用户不需要完成固定话题或阶段，并可提前生成证据有限报告。

该结果不是标准化心理测验。它不得用于跨人、跨议题、跨时间排名、人格判断、职业/留学建议或替用户作决定。

## 固定观察视角

| key | 名称 | 可观察的用户行为 |
| --- | --- | --- |
| `problem_definition` | 问题界定 | 区分现象与待决定问题，说明目标、边界、约束、相关方或时限。 |
| `evidence_evaluation` | 证据评估 | 区分已知/未知与事实/假设，说明来源、可靠性、核验或改变判断的证据。 |
| `reasoning_argumentation` | 推理论证 | 说明理由、前提、推导、替代解释、反例或关键假设。 |
| `multiple_perspectives` | 多元视角 | 比较不同相关方、价值冲突、风险承担或短长期影响。 |
| `integrative_decision` | 整合决策 | 把判断转为可执行的下一步、取舍、优先级、责任、时点或备选。 |
| `dynamic_adjustment` | 动态调整 | 说明什么新信息、条件或反馈会使其调整、坚持或复盘。 |

维度定义固定；V6 允许议题和对话走向因人而异，但不允许按议题改写维度含义或把未谈及的维度视为低能力。

## 访谈期禁止的测量调度

访谈请求不得携带或由服务端推导：`target_dimension`、`coverage`、`coverage_ceiling`、`dimension_followups`、固定阶段、候选题库、反事实必答、最终整合必答或 8–12 轮规则。质量标记可用于后续人工审计，不能重写自然问法或指挥下一题。

## 归属、增量快照与证据门槛

增量整理器使用版本化五级行为 Rubric：`agent_test_v2_five_level`。六个维度各有 1–5 的行为锚点，完整标准见 [V6 五级评分标准](V6_SCORING_RUBRIC.md)。访谈官不接收五级锚点、当前分数或覆盖状态，避免为了补分而引导对话。

在 enforce 合同中，服务端先为 user turn 生成绑定精确 occurrence 的 span candidate ID；归属器只按 ID 返回来源和关系分类，不回显原文或自行计算偏移。服务端按 ID 权威物化 span，复核角色、原文切片、occurrence、非重叠、文本哈希、逐字稿与资产指纹，再独立计算 `eligible | context_only | manual_review`。外部原文/转述、问题或请求、裸引用、裸赞同与不确定来源不能直接支持数字分；参与者自己的理由、批评、拒绝、取舍、行动或调整才可进入评分候选。

评分器只接收 eligible span registry，并重新输出当前完整六维结果：

```json
{
  "dimension_key": "evidence_evaluation",
  "score": 1,
  "sufficient": true,
  "evidence_refs": [{ "attribution_span_id": 27 }],
  "reason": "基于原话的简短解释",
  "confidence": 0.0
}
```

`score` 只能为 1–5 整数或 `null`。数字分数必须同时满足：

1. 至少一个 `attribution_span_id` 指向同一检查、同一逐字稿和同一资产下经服务端验证的 eligible span；
2. 评分器将该维判为 `sufficient=true`；
3. 原话呈现的是相关的可观察思维/决策行为，而不仅是访谈官提示、用户自评标签或一句“我很擅长/不擅长”。

任何条件失败时，`score=null`。AI/论文/他人的原文或转述、给 AI 的问题、系统事件、Prompt、模型自行概括、裸赞同或用户自我标签本身都不能成为能力证据。模型不得自报 `eligible`，也不得从原始整段重新挑 quote。引用无效、来源不明、评分格式修复、低置信度、缺维，或某维唯一证据来自 `strong_scaffold` 时均应触发人工复核建议；提示强度本版不自动改分。

评分时先匹配用户原话中的行为锚点，再选择达到的最低等级；回答长度、表达流畅度、态度和方案偏好不自动提高分数。4–5 分需要原话明确呈现相应锚点，证据不足使用 `IE`，不记为 1 分。

用户端状态映射为：

- `sufficient`：证据充分，可显示分值和对应原话。
- `limited`：有相关表达但不足以支持数字分数，显示“证据有限”。
- `unmeasured`：本次对话未充分触及，显示“未充分测得”。

未校准 `confidence` 只保留在本地复核台，绝不显示为用户端数字结论。

当前快照只有同时满足以下条件才是 `ready`：已保存的非重复用户回答至少为 8；六维全部具有数字分数、`sufficient=true` 和至少一条有效 quote。部分充分或不足八轮时完整快照仍必须保存，未充分维度保持 `null/IE`。没有展示机会、没有谈到行动/调整不能作为低分证据，数字分必须来自用户直接表达的行为。冻结前检查 ID、逐字稿指纹和评分资产必须完全匹配；冻结后同一结果直接提升为正式评分、证据和报告，不能重新评分或丢弃最后一轮。

## 报告表达

报告可以列出六维、可核验原话、优势、可继续思考的方向和实验性边界。参与者报告可显示综合总分，但必须是证据充分维度的等权平均换算为 20–100 分；未测得维度不按 0 分计入，并说明参与计算的维度数。不得输出人格结论、职业/留学排名或替用户选择。建议不得伪装成测量证据，也不得把未测得说成低分。
